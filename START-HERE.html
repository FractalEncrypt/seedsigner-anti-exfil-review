Download and test anti-exfil signing

Read this before running

Most of this project's new anti-exfil code and documentation were written with OpenAI GPT-5.6 and GPT-6.1 under my direction. I tested the workflows extensively on physical devices, but I cannot personally audit all of the source code or cryptography.

Adversarial AI review of the work included V12, DeepSeek v4.1 Flash, GLM 5.3 (High and Flash Max), and Kimi K3 High. Those reviews and the device tests can miss subtle mistakes. They are not an independent human security audit. This disclosure describes our anti-exfil additions, not the authorship of the upstream projects.

I am sharing this experimental work for testing and independent review. Use disposable test seeds and testnet coins. Successful device tests are not a guarantee of security.

If you can review the code, challenge the assumptions and report what you find by creating an issue in the repo.

Try the extra QR exchange that protects ECDSA signing against malicious nonce choices. You can start with one SeedSigner or one Kern. After setup, choose live Testnet4 signing or prepared offline tests that need no coins.

This guide covers the Windows x64 tester kit, 2026-10-09. It includes the rebuilt Sparrow, Java, both device images, Kern's flashing tool, and the test cases. No Git, Docker, WSL, Python, JDK installation, or BIOS changes are needed. macOS and Linux download packages are not available for this kit. Developers can use the separate Windows and Linux source-build guides.

Use a device reserved for experimental testing. Public test seeds are known to everyone; keep your personal wallet seeds out of this test. The supplied transactions are fabricated for offline signing and cannot be broadcast.

1. Get the Windows tester kit

From the project releases, choose Airgap Anti-Exfil tester kit — Windows x64 — 2026-10-09. Download:

  • AexTest-20261009.zip
  • AexTest-20261009.zip.sha256

The ZIP is the only package you need for this guide. The small .sha256 file lets you check the download. Optional source and review archives are for people inspecting or rebuilding the software. GitHub's automatically added Source code downloads are not the tester kit.

You will also need a computer camera and Windows 10 or 11, x64. For SeedSigner, use the supported Pi Zero revision 1.3 with a test microSD card and a card reader. For Kern, have a USB data cable and the wave_7b ESP32-P4 revision v1.3 board supported by this image.

2. Check the download and extract it

Put the ZIP and its .sha256 file in the same folder. Open that folder in File Explorer, click the address bar, type powershell, and press Enter. Run this check before opening any application in the kit:

$package = 'AexTest-20261009.zip'
$line = (Get-Content -LiteralPath ($package + '.sha256') -Raw).Trim()
if ($line -notmatch '^([0-9a-f]{64})  (.+)$') { throw 'Invalid checksum file' }
$expected = $Matches[1]
if ($Matches[2] -ne $package) { throw 'Checksum names a different file' }
$actual = (Get-FileHash -LiteralPath $package -Algorithm SHA256).Hash.ToLowerInvariant()
if ($actual -ne $expected) { throw 'Checksum mismatch. Stop and download again.' }
Write-Host 'Checksum matched. You can extract the kit.'

The result must say Checksum matched. Then right-click the ZIP and choose Extract All. Open the AexTest folder inside the extracted folder. Everything is already arranged; there are no further ZIPs to unpack:

Keep the whole extracted folder together. A matching checksum detects an incomplete or altered download; it does not by itself authenticate the publisher. If you want to authenticate the release as well, use the optional check below before continuing to flashing or opening Sparrow.

3. Flash SeedSigner — skip if you only use Kern

The image is for a Pi Zero. Flashing replaces everything on the selected card. Remove unrelated removable drives to make the test card easy to identify.

If you already have balenaEtcher installed, open it now. Otherwise install balenaEtcher before continuing.

  1. Disconnect SeedSigner's power cable. Remove its microSD card and put the card in your computer's card reader.
  2. Open Etcher. Click Flash from file and choose the .img in the kit's SeedSigner folder.
  3. Click Select target, select the test microSD card, then click Flash.
  4. Wait for flashing and validation to finish successfully. Safely eject the card, remove it from the reader, and put it back in SeedSigner.
  5. Reconnect power. Confirm the menu opens and the buttons and camera work.
  6. Open Settings → Persistent Settings and enable persistent settings.
  7. Open Settings → Advanced. If you use a SeedSigner Plus, first open Hardware → Display type and select st7789 320x240, then return to Advanced.
  8. In Advanced → Bitcoin Network, select Testnet.
  9. In Advanced → Anti-exfil signing, select Required. Return to the main menu. These settings are ready before you load a seed.

If validation fails or SeedSigner does not boot, stop here and report that result. Otherwise continue below.

4. Flash Kern — skip if you only use SeedSigner

This kit includes firmware for wave_7b, ESP32-P4 revision v1.3. Flashing replaces the installed firmware.

  1. Open the kit's Kern folder and double-click Check-Package.cmd. All checks must pass.
  2. Connect Kern using a USB data cable. Open Windows Device Manager. Under Ports (COM & LPT), find the entry that appears when Kern is connected. Note its port, such as COM5.
  3. Double-click Flash-Kern.cmd and enter that COM port.
  4. The tool checks for ESP32-P4 revision v1.3 automatically and stops without writing if it cannot confirm that identity. When it asks Type FLASH to write this firmware, type FLASH and press Enter. Wait for the write and hash checks to finish.
  5. Start Kern and confirm its screen, touch controls, and camera work.

If no port appears, try another data cable and USB port. If the port appears but identification fails, report the output before trying a different firmware. The supplied tool includes esptool; no Python installation is needed.

5. Open Sparrow

The launcher automatically uses a separate test profile. Your regular Sparrow installation and wallets are not needed. This test profile remembers its own wallets and signing sessions between restarts; you do not need to choose or create a profile manually. The launcher is not Authenticode signed; a Windows reputation prompt is separate from the download checksum check.

  1. Double-click Start-Sparrow.cmd in the kit's top folder. Use this launcher again whenever you restart. The file under Sparrow/Start-Native-Sparrow.cmd is an internal helper used by this launcher; you do not need to open it.
  2. If the welcome dialog appears, close it with the X at its top-right. On a first launch, Sparrow opens with no wallet loaded and the server connection off.
  3. Confirm the top-right network label says Testnet4. Leave the server connection off until you choose a testing path below.

If the camera will not open during a scan: check Windows Settings → Privacy → Camera and allow desktop apps to access the camera. A permission prompt is not necessarily shown when Sparrow first uses it.

6. Choose your testing path

Setup is complete. Choose one guide and follow it from start to finish:

  • Live Testnet4 signing — create or load your disposable test wallet, fund it with testnet coins, then sign and broadcast a transaction. This is the familiar wallet-testing route, with both singlesig and optional multisig steps.
  • Offline signing tests — use the prepared public seeds, PSBTs, and HTML QR viewer. No coins or server connection are needed. Start with singlesig, then optionally try multisig, rejection cases, and recovery checks.

Each guide contains its own wallet setup and signing steps; neither sends you back here mid-test. Open FEEDBACK.html, record what you tried, and click Save feedback HTML. Reopen the downloaded HTML to keep editing. A photo or a sentence about where you got stuck is enough.

For a focused report, use offline feedback or live feedback. Every result has a Steps link. Leave tests you did not try Not run.
