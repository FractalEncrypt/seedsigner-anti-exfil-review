# Publication boundary after P4/P5

P4 assembled the v2 candidate, P5 accepted it, and P5.1 accepted the
checkout-independent Git-blob archive repair. P4.2 is a publication-facing
editorial update that requests outside review without changing product source,
protocol behavior, or accepted limitations.

Those gates authorize and perform no tag, push, release, GitHub issue comment,
upstream pull request, firmware publication, or public distribution. They make
the candidate eligible only for a separately owner-authorized publication
operation. Model-based acceptance does not imply independent human or community
security review.

Any publication authorization must name the exact review-hub commit/tree,
archive filename/bytes/SHA-256, Drongo/Sparrow/Kern candidate commits, proposed
tags/branches, release assets, repositories to push, and any issue update. A
change after accepted review invalidates the reviewed archive and requires a
new manifest/hash and review disposition proportional to the change.
